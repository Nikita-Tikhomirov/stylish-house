# Сборщик римских штор: инструкция оператора

## Что делает программа

Сборщик последовательно проходит 46 заданных категорий `rimskie.com`. Он сохраняет:

- все уникальные товары из выбранных категорий;
- полный исходный заголовок и текст карточки;
- цену донора как справочное поле, без подключения к калькулятору;
- характеристики для будущих фильтров;
- принадлежность одного товара ко всем найденным категориям;
- первую фотографию как настоящий локальный файл WebP.

Рерайт пока не выполняется. Модель для рерайта подключается отдельным этапом после окончания сбора.

## Как запустить

1. Дважды нажать `start-rimskie-gui.cmd` в корне проекта.
2. В браузере откроется локальная панель `http://127.0.0.1:43127`.
3. Для нового прохода нажать `Начать новый сбор`.
4. Для существующего прохода выбрать его слева и нажать `Продолжить`.

Панель работает только на этом компьютере. На VPS она не публикуется.

## Как программа продолжает после остановки

Очередь и каждый завершённый этап записываются на диск. После перезапуска компьютера или программы нужно снова открыть панель, выбрать тот же запуск и нажать `Продолжить`.

Уже принятый товар повторно не запрашивается. Уже проверенная фотография повторно не скачивается. Данные, временно собранные рабочей браузерной сессией в `browser-seed`, при продолжении автоматически проверяются и включаются в основной checkpoint вместе с фактическим часовым журналом запросов.

## Интервалы и проверки сайта

Сбор выполняется строго в один поток. Между HTML-страницами программа ждёт 2–4 минуты, между карточкой и фотографией — 1–2 минуты. Дополнительно действует предел 20 учитываемых операций за скользящий час. При достижении лимита программа сама ждёт освобождения следующего места.

Сетевые ошибки, `403` и `429` не сбрасывают очередь: применяются сохранённые паузы 2, 5 и 15 минут, после чего запрос повторяется. Полная проверка человека не проходится автоматически. При ней checkpoint остаётся на диске, а после ручного завершения проверки сбор продолжается с того же места.

## Где находятся файлы

Все рабочие данные находятся вне диска `C:`:

```text
G:\stylish-house-data\rimskie-imports\<run-id>\
├── config.json          неизменяемые настройки и 46 исходных категорий
├── state.json           основной checkpoint и очередь
├── control.json         состояние запуска, паузы и остановки
├── events.ndjson        журнал ожиданий, запросов и ошибок
├── memberships.ndjson   связи «товар — категория»
├── products\             один JSON на каждый товар
├── images\               первое фото каждого товара в WebP
├── sources\              состояние прохода по категориям
├── browser-seed\         временные данные рабочей браузерной сессии
├── profile\              отдельный профиль Chrome сборщика
└── export.json          появляется после успешного формирования пакета
```

Например, товар `11889` хранится как `products\11889.json`, а его фотография — как `images\11889.webp`.

## Что означают кнопки

- `Пауза` — безопасно остановить работу с возможностью продолжения.
- `Продолжить` — проверить сохранённые данные и возобновить тот же запуск.
- `Остановить` — окончательно закрыть запуск; после этого продолжение запрещено.
- `Сформировать пакет` — создать проверенный `export.json`; кнопка доступна только после полного завершения.
- `Открыть папку` — открыть каталог текущего запуска на диске `G:`.

## Как данные попадут на сайт

Сначала сбор должен закончиться и сформировать `export.json`. Затем пакет проверяется без записи в базу:

```powershell
php artisan catalog-import:ingest 'G:\stylish-house-data\rimskie-imports\<run-id>\export.json' --dry-run
```

После проверки пакет можно загрузить в закрытый staging-каталог. Публикация, подключение цен к расчёту и рерайт — отдельные этапы. Перед любыми изменениями production-базы обязателен свежий проверенный бэкап базы.
